\section{Exploratory analysis and quality controls}

The pipeline writes source inventory, key and join audits, duplicate summaries,
invalid-record summaries, missingness profiles, class distributions, temporal
aggregations, product/card/device/email breakdowns, and outlier reports.

These reports are descriptive. A higher observed fraud rate for a device or
product group does not establish a causal relationship; the group can be
confounded by transaction mix, time, or missingness.

\section{Feature engineering}

\subsection{Time features}

Time features include transaction day, week, hour, a day-of-week proxy, age in
days, and a night-transaction flag. The raw \texttt{TransactionDT} is retained
in the canonical feature order.

\subsection{Amount features}

Amount processing includes the raw value, logarithm, capped value, decimal
component, amount band, and ratios/deviations relative to card history. Saved
outlier thresholds are learned from training and applied forward.

\subsection{Missingness and presence}

The pipeline produces counts and ratios for selected/identity missing values and
flags for identity, device, payer/recipient email, distance, address, and shared
email domain presence.

\subsection{Anonymized behavior fields}

Selected \texttt{C1--C14}, \texttt{D1--D15}, and distance features are retained.
Their public semantic meaning is limited, so this report describes them as
behavioral/anonymized variables rather than inventing business definitions.

\subsection{Historical entity features}

Card, email, and device keys produce prior transaction counts and amount
aggregates. Card history additionally includes standard deviation and time since
the previous transaction. Training rows use prior-window history; later splits
receive lookups fitted only from the training window.

\subsection{Categorical features}

The seven categorical fields are:

\begin{itemize}
  \item \texttt{ProductCD}, \texttt{card4}, and \texttt{card6};
  \item \texttt{DeviceType} and \texttt{device\_family};
  \item \texttt{M4} and \texttt{amount\_band}.
\end{itemize}

String indexers are fitted on training. The extracted mappings are serialized
with the model for Spark-free request-time encoding.

\section{Missing-value and class-imbalance strategies}

Numeric medians and categorical missing policies are persisted. At serving,
missing values that remain after categorical mapping use a numeric sentinel.
This is compatible with the current tree models, but the sentinel must remain
part of the model contract.

The primary training set uses class weights and keeps all 412,956 training
rows. A second set undersamples legitimate examples:

\section{Verification result}

The saved verifier reports 82 checks passed and no failures. It validates
dataset presence, row counts, identifiers, labels, weights, feature order,
schema hashes, chronological order, split overlap, and required artifacts.

One lifecycle inconsistency remains. The regenerated top-level manifest records:

\begin{lstlisting}
verification_pending
\end{lstlisting}

The dedicated verification report records the later terminal value:

\begin{lstlisting}
ready_for_downstream_training
\end{lstlisting}

Future finalization should write this terminal verifier result back to the
manifest atomically.

\section{Data limitations}

\begin{itemize}
  \item Feature semantics are partly anonymized.
  \item Entity aggregates are batch features; a production online path is not
  implemented.
  \item The training matrix is collected to pandas before estimator fitting.
  \item There is one chronological validation window rather than temporal
  cross-validation.
  \item Native Windows is not the canonical full Parquet execution path.
  \item The local processed tree is large and intentionally excluded from Git.
\end{itemize}
