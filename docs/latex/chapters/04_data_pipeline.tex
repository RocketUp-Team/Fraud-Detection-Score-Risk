\section{Feature engineering}

\subsection{Time features}
Time features capture transaction day, week, hour, day-of-week, age, and night flags. Raw \texttt{TransactionDT} is retained in canonical feature order.

\subsection{Amount features}
Amount features include raw value, logarithm, capped value, decimal part, amount band, and card history deviations. Outlier thresholds fit on training only.

\subsection{Missingness and presence}
Missingness counts/ratios and presence flags cover identity, device, email, distance, address, and domain presence.

\subsection{Anonymized behavior fields}
Selected \texttt{C1--C14}, \texttt{D1--D15}, and distance attributes are retained as anonymized behavioral indicators.

\subsection{Historical entity features}
Card, email, and device keys provide prior transaction counts, amounts, standard deviations, and recency, fitted strictly from training.

\subsection{Categorical features}
Seven categorical fields (\texttt{ProductCD}, \texttt{card4}, \texttt{card6}, \texttt{DeviceType}, \texttt{device\_family}, \texttt{M4}, \texttt{amount\_band}) use training-fitted string indexers serialized with the model.

\section{Data limitations}

\begin{itemize}
  \item Feature semantics are partly anonymized.
  \item Entity aggregates are batch features; a production online path is not
  implemented.
  \item The training matrix is collected to pandas before estimator fitting.
  \item There is one chronological validation window rather than temporal
  cross-validation.
  \item Native Windows is not the canonical full Parquet execution path.
  \item The local processed tree is large and intentionally excluded from Git.
\end{itemize}
