\section{Problem context}

Online transaction fraud is an imbalanced classification problem with rare positive instances and asymmetric error costs \parencite{ieeecis2019,amazonfraudbenchmark}.

\begin{quote}
How can a reproducible big-data pipeline, an imbalanced-classification model, an explainable scoring API, and a human-review interface be integrated into one auditable fraud risk scoring system?
\end{quote}

\section{Objectives \& research questions}

\begin{itemize}
  \item Ingest and validate the \val{1.29~GB} IEEE-CIS dataset via Apache Spark.
  \item Construct leakage-free chronological dataset splits (\texttt{train}, \texttt{val}, \texttt{holdout}).
  \item Compare MLlib DecisionTree, LightGBM, XGBoost, and CatBoost classifiers.
  \item Serve packaged models behind a FastAPI scoring API with TreeSHAP explanations and React UI.
\end{itemize}

\begin{description}[style=multiline,leftmargin=1.6cm,labelwidth=1.2cm]
  \item[RQ1:] Can raw data be processed without identifier overlap or temporal leakage?
  \item[RQ2:] Which classifier achieves highest validation PR-AUC and retains holdout performance?
  \item[RQ3:] Can the model be served efficiently without a Spark dependency at request time?
  \item[RQ4:] What technical boundaries separate the academic demo from production readiness?
\end{description}
